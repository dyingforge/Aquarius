# 07: 审查并解决冲突候选

**What to build:** 当 Aquarius 发现互相矛盾、低置信或敏感的画像与策略候选时，它不会自动污染当前记忆，而是让用户从 review queue 查看证据并决定采纳、合并、拒绝或按时间变化处理。

**Blocked by:** 05: 跨案例自动沉淀画像与策略; 06: 预览确认并提交记忆修正

**Status:** ready-for-agent

- [ ] 未解决冲突、低置信或敏感候选进入 review queue，普通问答默认不把它们当作当前事实。
- [ ] 用户能通过 CLI/API 查看候选内容、支撑证据、反对证据、置信理由和拟议操作。
- [ ] 用户可以选择采纳一个版本、合并、拒绝或解释为时间变化；所有选择先显示最终 diff。
- [ ] review 决定使用 expected HEAD 防止基于旧证据提交，并记录用户审批、时间和关联 memory ID。
- [ ] 解决冲突后，active memory、summary 和 FTS 保持一致；同一 review 不可被重复执行。
- [ ] 新证据再次推翻已解决结论时创建新的 review，而不是静默覆盖用户决定。
