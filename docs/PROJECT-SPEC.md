# PROJECT-SPEC — 项目定位、产品目标与功能范围

## 1. 一句话定位

Aquarius 是一个**单用户、本地运行的长期记忆服务**：每天消化你在编码 Agent 里的会话，把值得留存的东西沉淀成可审计的长期记忆，并在你提问时用当前有效的记忆回答——带引用，不编造。

## 2. 目标用户与场景

唯一的目标用户是**一个人**：在本机用 Codex 等 Agent 写代码、且希望 Agent 与工具逐步「记住」自己工作方式的人。

典型场景：

- 「我上周不是说过这个仓库统一用 pnpm 吗，怎么又用 npm 了？」
- 「这个项目发布前要跑哪些检查？」（答案来自过去的实际做法，而不是通用建议）
- 「我之前为什么放弃了那个方案？」（答案来自当时的经历记录与证据）
- 「我这套审查流程已经用过三次了，能不能固化成可复用的 Skill？」

## 3. 产品目标

1. **可信的记忆**：每条记忆都能追到来源证据与置信理由；模型不能凭一句话改变当前事实。
2. **可控的写入**：用户明确要求立即生效；模型推断必须跨案例积累；冲突与敏感内容必须人工裁决。
3. **可恢复的存储**：Git 是事实源，删掉数据库不丢记忆；任何一次写入都可审计、可回滚。
4. **本地与私有**：只监听 loopback，只用一个本地 token，凭据永不入库，默认关闭远程 tracing。
5. **有界的智能**：模型只负责提取、合并、回答与合成；判定与写入由确定性代码完成。

## 4. 功能范围（首版）

### 4.1 已实现

**摄取**

- Codex session 适配器：活动目录、归档目录、session index。
- 增量：稳定事件标识 + 内容哈希 + adapter schema version；重复扫描幂等。
- 延后处理仍在写入的文件；归档迁移不重复生成记忆。
- 预脱敏：API key、token、密码、私钥、连接串、JWT、认证头，含中英自然语言写法。
- 未知事件类型与截断尾部安全跳过，不阻塞批次。

**记忆**

- 四类记忆：经历、用户画像、策略、Skill。
- 确定性门禁：经历一次有效证据即可；推断画像/策略需两个独立 case + 高置信 + 无冲突；用户明说立即生效。
- 状态流转：active / candidate / superseded / forgotten / retired / rejected。
- 冲突、低置信、敏感内容进入 review 队列，不作为当前事实。
- 修正：自然语言 → 定位 → diff 预览 → 确认（带 expectedHead）→ 提交 → 更新摘要与索引。
- 忘记只移出当前视图，明确不承诺擦除 Git 历史。

**检索与问答**

- 渐进式加载：小摘要 → FTS 候选 → 相关性选择 → 只加载选中记忆与必要证据。
- 回答标注 memory ID；证据不足或冲突时明确不确定性。
- FTS 索引可从 Git HEAD 完整重建；中文用 bigram 增强。

**Skill 生命周期**

- 候选自动生成（≥3 独立成功 case、≥2 种任务特征）。
- 发布必须用户批准；静态门禁（格式、来源、敏感信息、路径、依赖声明、同名冲突）。
- 确定性安装到 Codex skills 目录，带 managed 标记；绝不覆盖外部同名 Skill。
- 支持拒绝、retire、回滚到上一已发布版本。

**运行与运维**

- Fastify 本地 API + 完整 CLI。
- 每日 03:00（Asia/Shanghai）调度；错过窗口启动补跑；每自然日至多一次自动批次。
- 单写入者任务队列、优先级、有界重试、启动对账。
- `doctor` 自检；结构化、脱敏的本地日志。

### 4.2 首版不做

明确排除，避免范围蔓延：

- 多用户、账号体系、云端部署与 Postgres。
- Web UI（只用 CLI 与 localhost API）。
- Codex 之外的真实 session 适配器（保留接口契约）。
- 向量检索与 embedding。
- 完整原始 session 归档复制。
- 让 SDK 的 beta Memory 直接写 canonical repository。
- Skill 自动发布、可执行代码 Skill、自动授权工具。
- Git 历史级敏感信息擦除。
- 多模型路由、自动升级模型、永久推理循环。

## 5. 非功能要求

| 维度 | 要求 |
| --- | --- |
| 安全 | 只监听 `127.0.0.1`；所有接口需本地 bearer token；非 loopback 来源拒绝；凭据在模型调用/日志/Git 之前脱敏；记忆仓库权限 0700、token 文件 0600 |
| 隐私 | 不复制完整会话；只保存脱敏后的必要证据；远程 tracing 默认关闭；日志只记延迟、token 数、模型版本与错误类别 |
| 可靠 | 写入原子（隔离暂存 + CAS）；崩溃后可对账；任务有界重试；一个坏会话不影响其他会话 |
| 可恢复 | SQLite 可删可重建；FTS 与 summary 均为 Git HEAD 的派生投影 |
| 可观测 | 每次摄取产生 audit 记录（不含原文与凭据）；`doctor` 覆盖全部依赖并给出可执行建议 |
| 可测试 | 默认使用确定性 Agent 替身，测试不发网络请求；真实模型调用单独 smoke |

## 6. 成功判定

用一个具体场景验收：本机连续三天的 Codex 使用之后——

1. 服务每天自动消化新会话，重复扫描不产生重复记忆。
2. 提问能拿到带 memory ID 的回答；证据不足时它说「不知道」。
3. 跨三个不同任务的同一做事方式被识别为策略，并在达标后生成 Skill 候选。
4. 一条错误记忆可以被自然语言修正，确认前不影响任何东西，确认后立即生效。
5. 出现矛盾陈述时，两条都不会自动成为当前事实，而是等你裁决。
6. 删除 SQLite 数据库并重建索引后，检索结果与之前完全一致。

以上 1–6 均有自动化测试覆盖，其中 1、2、4 已在真实 Codex 会话上人工走过一遍。
